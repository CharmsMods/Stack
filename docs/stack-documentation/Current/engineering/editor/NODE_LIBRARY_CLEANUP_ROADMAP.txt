NODE LIBRARY CLEANUP ROADMAP
Documentation-only roadmap for future source changes.

Purpose
This file turns the audit into a practical cleanup sequence. It should be used after
reviewing `docs/stack-documentation/Info/engineering/editor/NODE_LIBRARY_AUDIT.txt`,
`docs/stack-documentation/Info/engineering/editor/NODE_LIBRARY_CHANNEL_COMPATIBILITY.txt`,
and `docs/stack-documentation/Info/engineering/editor/NODE_LIBRARY_ADVANCED_UI_CANDIDATES.txt`.

Current implementation status
The first professionalization pass has been implemented in source. Registered layer
descriptors now include lifecycle status, channel policy, browser visibility, notes,
and tags. Alpha Protect and Text Overlay are hidden from the add-node browser while
remaining registered for compatibility. Expand Canvas is still visible but marked
experimental/rework-needed. Complex Node eligibility is now derived from
NodeSurfaceSpec RichExpandedSurface instead of new advanced nodes requiring dedicated
type-ID branches.
The second focused cleanup pass excludes the unregistered legacy aggregate layer
files from the CMake source glob without deleting them, so they no longer add compile
surface area but can still be consulted for migration decisions.

Guiding principles
Do not remove nodes just because they are old. First decide whether saved projects
need migration support.
Keep normal effect nodes one-input/one-output. Do not add four pins to ordinary
effects for channel editing.
Make channel identity metadata-driven through graph lineage.
Promote professional behavior through metadata, clear categories, warnings, and
tests, not scattered hardcoded checks.
Separate true canvas/resolution changes into explicit Reformat/Transform nodes.

Priority 2 - Remove hardcoded advanced-node type checks
Status: Mostly implemented.

Previous issue:
Complex Node access was partially generic, but code hardcoded BackgroundPatcher and
ColorGrade in places such as floating toolbar logic and UI fallback labels.

Desired behavior:
Any layer whose NodeSurfaceSpec says RichExpandedSurface gets Complex Node access.
Toolbar buttons are generated from node metadata, not specific type IDs.
Sidebar title uses node title or registry display name generically.
Canvas tool availability comes from NodeSurfaceSpec.usesCanvasTool.

Current behavior:
The graph surface, context menu, sidebar, and floating toolbar now use
RichExpandedSurface generically. Remaining type-specific logic is limited to existing
icon/short-label polish for Background Remover and 3-Way Color Grade.

Acceptance tests:
Background Remover and 3-Way Color Grade still show advanced editors.
A new test layer with RichExpandedSurface appears in the Complex Node toolbar without
adding a type-ID-specific branch.
Compact layers do not create advanced toolbar buttons.

Reason:
These are not directly registered in LayerRegistry, but CMake globbing compiles them.
They appear to be older aggregate versions replaced by split nodes.

Current behavior:
CMake excludes these legacy aggregate .cpp/.h files from SRC_FILES. The files remain
in the repository for now, instead of being deleted, because saved-project migration
has not been fully designed.

Safe cleanup path:
Search saved project examples and deserialization aliases for their type IDs.
If no compatibility is needed, remove the files and confirm the build.
If compatibility is needed, keep deserialization aliases but migrate loaded projects
to replacement nodes.
If unsure, move them to an archive folder only after build rules stop compiling them.

Acceptance tests:
Release build succeeds after removing or excluding confirmed stale files.
Existing projects that use current split node type IDs still load.
Any old projects selected for compatibility testing either load or produce a clear
migration warning.

Priority 4 - Rework or hide the strongest problem nodes
Alpha Protect:
Current issue: Depends on original source alpha through ExecuteWithSource.
Why this is awkward: Alpha can now be split, edited, recombined, and routed as a
first-class channel stream.
Recommended direction: Replace with explicit alpha tools such as Preserve Alpha,
Replace Alpha From Mask, Clamp Alpha, Invert Alpha, or Premultiply/Unpremultiply if
those become needed.
Interim choice: Implemented. Marked deprecated/rework-needed and hidden from the
add-node browser while preserving the descriptor for compatibility.

Expand Canvas:
Current issue: Simulates padding inside a fixed canvas instead of changing raster
dimensions.
Recommended direction: Move this concept to future Reformat / Canvas Resize nodes.
Interim choice: Mark experimental or rework-needed so users do not believe it changes
the output canvas.
Current status: Implemented as experimental/rework-needed metadata. It remains
visible for now because it may still be useful while true Reformat nodes do not exist.

Text Overlay:
Current issue: Registered node, but C++ text texture generation is placeholder.
Recommended direction: Either implement a true text overlay/editor workflow or hide
the node until ready. The graph-native Text image generator may cover some needs in
the meantime.
Current status: Implemented as hidden from the add-node browser while preserving the
descriptor for project compatibility.

Background Remover:
Current issue: Valuable advanced node, but has placeholder/unused brush, flood, AA,
and patch state.
Recommended direction: Either implement those controls or remove them from state/UI
until a real matte-editing pass exists. Consider adding a mask-output mode.

Priority 5 - Define single-channel effect contract
The current channel pipeline is powerful, but many effects were written as RGB image
passes. Define these rules before heavy refactoring:

A channel-derived image stream is a scalar field represented as an image texture.
Scalar operations should read and write the scalar value consistently.
Color operations should either:
Use grayscale interpretation with a warning, or
Be marked full-image preferred/full-image only.
Alpha-sensitive operations must not silently use unrelated original alpha.
Spatial operations may be allowed, but should warn that per-channel transforms can
create color misregistration after recombine.

Acceptance tests:
Image -> Split R -> Brightness -> Output produces red-only output with expected
missing-channel defaults.
Image -> Split R -> Blur -> Output works and keeps R lineage.
Image -> Split R -> Saturation warns or has documented behavior.
Image -> Split A -> alpha utility -> Channel Combine A works predictably.

Priority 6 - Build professional test scenes
Create manual or automated graph scenarios:
Full image: Image -> Brightness -> Output.
Channel scalar: Image -> Split R -> Brightness -> Output.
Channel blur: Image -> Split G -> Gaussian Blur -> Output.
Recombine: Image -> Split R/G/B -> Channel Combine -> Output.
Multi-source: Image A R plus Image B B -> Channel Combine -> Output.
Resolution mismatch: portrait source plus landscape source into Channel Combine.
Multiple outputs: two outputs with different source images and different reference
canvases.
Mask crossover: Noise Mask -> Levels Mask -> Channel Combine A.
Advanced UI: Background Remover and 3-Way Color Grade open through generic advanced
node eligibility.

Priority 7 - Professional node library polish
Add searchable tags to nodes.
Examples:
Brightness: exposure, light, channel safe.
Gaussian Blur: soften, mask, channel safe.
Channel Combine: rgba, recombine, channels.
Background Remover: key, matte, alpha, cutout.

Add short help text/tooltips.
Every node should state whether it is full-image, channel-safe, mask, generator,
analysis, or output.

Add library grouping cleanup.
Consider separating Effects / Damage into:
Stylize.
Artifacts.
Lens / Distortion.
Video / Analog.

Add deprecation visibility.
Deprecated nodes should load from existing projects but not appear in the add-node
browser unless a developer/debug option is enabled.

Add implementation templates.
New layer nodes should have a predictable checklist:
Registry descriptor.
Stable type ID.
Serialization and legacy aliases.
Channel policy.
Lifecycle status.
Advanced UI policy.
Shader initialization and cleanup.
Render tests or manual test graph.

Recommended next implementation order
1. Review saved-project compatibility for old aggregate layer type IDs and decide
   whether to add aliases/migration nodes.
2. Add deeper channel-policy warnings in the node browser and link/drop workflow.
3. Add smoke tests/manual test graphs for every category.
4. Rework Alpha Protect into explicit alpha-channel tools or remove it permanently.
5. Rework Expand Canvas into true Reformat / Canvas Resize behavior.
6. Decide whether Text Overlay should be finished as a rich editor node or replaced
   by graph-native Text generator workflows.
7. Revisit category names, tags, icons, and short labels after behavior is stable.

Do not do yet
Do not add four input pins to normal effect nodes.
Do not put fit/fill/crop behavior into Channel Combine.
Do not delete legacy files until project compatibility is checked.
Do not make advanced windows type-ID-specific for every future node.
Do not assume every RGB effect is meaningful on channel streams without a policy.
