# Editor Reliability and Performance Audit

Updated: 2026-07-28

## Goal

Make the Editor tab, node graph, render pipeline, shader math, and resource
lifetimes as reliable and performant as possible without changing intended
image quality.

## Current Focus

- Continue auditing allocation-size arithmetic, GPU allocation failure
  propagation, and render/cache ownership.
- Exercise render-worker publication, replacement, and cancellation under
  deep, wide, and highly shared graph shapes.
- Implement the accepted Phase 7B3 Constant Alpha transaction without
  weakening graph rollback, extent, or renderer ownership guarantees.

## Working Rules

- Preserve all pre-existing worktree changes; do not revert or rewrite them.
- Separate measured defects from hypotheses.
- Add a regression check when a defect has a practical deterministic trigger.
- Do not trade image precision, color correctness, or output quality for
  speed.
- Avoid creating or expanding monoliths. Split code at real ownership or
  responsibility boundaries when a large file mixes unrelated work.
- Use `.\build.cmd` as the primary Windows build verification path.
- Do not use computer-use.
