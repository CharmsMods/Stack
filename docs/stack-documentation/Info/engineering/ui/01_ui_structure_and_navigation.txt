STACK APPLICATION — UI STRUCTURE AND NAVIGATION
================================================
Researched from src/ source tree, May 2026

--------------------------------------------------------------------------------
OVERVIEW: ROOT-LEVEL TAB BAR
--------------------------------------------------------------------------------

The entire application is controlled by a single top-level tab bar named
"ProgramContextTabs" defined in AppShell.cpp (line 194). It contains exactly
five tabs in fixed order:

  Index 0: Library
  Index 1: Editor
  Index 2: Composite
  Index 3: Render
  Index 4: Bundler

These are defined as RootTabDescriptor structs in a local anonymous namespace
inside AppShell.cpp. The enum RootTabId (lines 21-27) assigns the integer IDs.
The labels "Library", "Editor", "Composite", "Render", "Bundler" are the exact
string literals passed to ImGui::BeginTabItem.

The root window itself is named "ModularStudioMain" (AppShell.cpp line 182) and
is set to fill the full viewport with no decorations (NoDocking, NoTitleBar,
NoCollapse, NoResize, NoMove). The background clear color is:
  glClearColor(0.1f, 0.11f, 0.12f, 1.0f) — a near-black dark slate.

Tab switching can be triggered programmatically via AppShell::RequestTabSwitch()
which sets m_RequestedTab. This is consumed each frame; if the selected tab
matches the requested tab, m_RequestedTab resets to -1. Both the Library module
and the file-drop handler call this to auto-navigate users after loading a project.

--------------------------------------------------------------------------------
TAB LAYOUT: WHICH MODULES HAVE DOCKSPACES
--------------------------------------------------------------------------------

Three of the five tabs set up their own internal DockSpace. Two do not.

EDITOR TAB — Has DockSpace "EditorDockSpace" (EditorModule.cpp line 197).
  First-time layout (static bool first) splits:
    - Left 25%: "Inspector Panel Sidebar"
    - Bottom 35% of remaining: "Scopes Panel"
    - Center remaining: "Canvas Viewport"

RENDER TAB — Has DockSpace "RenderDockSpace" (RenderTab.cpp).
  Layout splits into Inspector (left), Scene panel (right side), and Viewport
  (center). Additional floating windows: Camera, Final Render Settings,
  Final Render, Test Scenes.

BUNDLER TAB — Has DockSpace "BundlerDockSpace" (BundlerModule.cpp line 116).
  First-time layout:
    - Left 28%: "Bundler Settings"
    - Bottom 30% of remaining: "Bundler Diagnostics"
    - Center remaining: "Project Files"

LIBRARY TAB — No DockSpace. Library renders three child regions manually:
  LibraryHeader (fixed height 50px toolbar), LibrarySidebar (resizable, 170-360px
  wide), and LibraryGrid (remaining space). The sidebar and grid are separated
  by a draggable 6px splitter bar.

COMPOSITE TAB — Has its own DockSpace managed via m_WorkspaceDockId and an
  INI-string-based layout persistence system (CompositeModule.cpp).
  Windows: Layer pane, Selected Inspector, View Inspector, Export Inspector,
  Stage (canvas). Layout state is saved into m_WorkspaceLayoutIni as a string
  and can be reset.

--------------------------------------------------------------------------------
INTER-TAB DATA FLOW
--------------------------------------------------------------------------------

The AppShell manages the cross-tab state machine in OnTabChanged() (lines 306-348).

When the user leaves Composite and enters Editor:
  - If the selected Composite layer is kind=EditorProject and has originalSourcePng,
    the embedded project JSON and source pixels are decoded and applied to the
    Editor via ApplyLoadedProject().
  - m_ActiveSyncLayerId is set to the layer ID.

When the user leaves Editor and enters Composite:
  - If m_ActiveSyncLayerId is non-empty, the Editor's rendered output is
    captured via GetOutputPixels() and pushed into CompositeModule::UpdateLayerData().
  - m_ActiveSyncLayerId is cleared.

This two-way sync only fires on actual tab transitions, not continuously.

The Library tab fires tab switches to indices 1, 2, or 3 (Editor, Composite,
Render) depending on what the user opens a project into. The active tab index
is passed as int* activeTab into LibraryModule::RenderUI().

--------------------------------------------------------------------------------
POPUP AND MODAL OWNERSHIP
--------------------------------------------------------------------------------

AppShell owns two modal popups rendered outside all tabs:
  - "Editor Project Already Open##AppShell" — asks Save & Continue, Discard &
    Continue, or Cancel when trying to load a project when the Editor already
    has one open.
  - "Save New Editor Project##AppShell" — input text for a project name when
    saving a project that has no file name yet.

These are triggered via m_ShowEditorSavePrompt and m_ShowEditorNamePrompt booleans
that are opened as popups in the NEXT frame via ImGui::OpenPopup(). This is the
correct pattern to avoid calling OpenPopup during EndTabItem.

The Library module has its own preview popup ("Library Project Preview") which
is a full-screen modal overlay, not a native ImGui popup. It is rendered by
calling LibraryModule::RenderGlobalPopups() from AppShell after EndTabBar.

--------------------------------------------------------------------------------
FIRST-TIME LAYOUT BEHAVIOR
--------------------------------------------------------------------------------

Editor's dockspace layout is controlled by a static bool `first` (EditorModule.cpp
line 200). It fires once per application run. There is no persistence of the
layout split ratios across sessions. Closing and reopening resets to defaults.

The Bundler does the same with static bool `firstLayout` (BundlerModule.cpp line 119).

The Composite tab is the only one with layout persistence via m_WorkspaceLayoutIni,
which stores the full imgui.ini section for the workspace.

The RenderTab uses m_RenderDockLayoutBuilt (line 116 in RenderTab.h) to guard
its layout initialization.

--------------------------------------------------------------------------------
SPLASH SCREEN
--------------------------------------------------------------------------------

A separate GLFW window is created for the splash screen during Initialize()
(AppShell.cpp line 390-537). It is a borderless, floating, transparent-framebuffer
window centered on the primary monitor. A second temporary ImGui context is
created for it. The splash window title is "Stack Loading".

The library refresh progress is shown as:
  - A 4px progress bar at the bottom of the splash image
  - Status text 30px from the bottom

The splash guarantees at least 2 seconds of visibility even if the library loads
faster. After the library loads, the splash is destroyed, the ImGui context is
switched back, and the main window is shown maximized.

--------------------------------------------------------------------------------
WINDOW NAMES USED AS IMGUI IDs (can break docking if renamed)
--------------------------------------------------------------------------------

These string literals identify dock targets. Changing them without migrating the
DockBuilder calls will break the layout:

  "ModularStudioMain"         — root host window (AppShell)
  "Inspector Panel Sidebar"   — Editor sidebar (EditorSidebar.cpp line 18)
  "Canvas Viewport"           — Editor image viewport (EditorViewport.cpp line 33)
  "Scopes Panel"              — Editor histogram/vectorscope (EditorScopes.cpp line 83)
  "Bundler Settings"          — Bundler left panel
  "Project Files"             — Bundler center file tree
  "Bundler Diagnostics"       — Bundler bottom log panel
  "Library Project Preview"   — Library full-screen preview modal
