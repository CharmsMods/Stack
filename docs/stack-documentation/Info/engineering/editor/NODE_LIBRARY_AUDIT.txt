NODE LIBRARY AUDIT
Generated from the current C++ node graph and layer registry.

Purpose
This report inventories the current node library, calls out stale or incomplete nodes,
and records recommended status labels for cleanup and professionalization passes.
The first source follow-up has added registry metadata and browser visibility policy,
but this report still treats actual node deletion and legacy file removal as future
work until saved-project compatibility is reviewed.

Status labels used in this report
Keep - The node is useful in the current workflow and should remain exposed.
Needs Fix - The node is useful but has correctness, UX, or pipeline issues to fix.
Rework - The node concept is useful, but the current implementation or semantics
  should be redesigned before the node is treated as professional/stable.
Hide/Remove Candidate - The node or file appears stale, redundant, or not suitable
  for the current library without a compatibility/migration decision.
Advanced UI Candidate - The node benefits from a dedicated Complex Node/sidebar
  editor or richer surface beyond compact inline controls.

High-level findings
The registered layer library currently contains 49 layer descriptors.
The layer descriptors now carry lifecycle status, channel policy, node-browser
visibility, lifecycle notes, channel notes, and tags. Hidden/deprecated descriptors
can still exist for saved-project compatibility while being omitted from the add-node
browser.

Graph-native nodes
Output - Keep.
Current behavior: Accepts a full image input or channel-mode R/G/B/A inputs. The
current channel system treats full-image and channel-mode output as mutually
exclusive modes. Missing channel-mode RGB inputs default to black and missing alpha
defaults to opaque.
Recommendation: Keep and continue treating it as one of the two sanctioned recombine
points, alongside Channel Combine.

Preview - Keep.
Current behavior: Analysis-style node for inspecting streams. It supports image and
mask-like inputs. It is useful while debugging full-image and channel pipelines.
Recommendation: Keep. Consider richer display labels later so channel previews say
which channel lineage they represent.

Histogram, Vectorscope, RGB Parade - Keep.
Current behavior: Scope nodes inspect image or mask outputs. They are useful for
professional workflows and channel debugging.
Recommendation: Keep. Later, scopes should show whether they are analyzing a
full-color image, a single-channel stream, or a mask.

Solid Mask, Linear Gradient Mask, Radial Gradient Mask, Noise Mask - Keep.
Current behavior: Procedural mask sources. These can feed layer masks, mix factors,
mask utilities, channel combine pins, and output channel pins where allowed.
Recommendation: Keep. These are foundational for compositing and channel work.

Invert Mask, Levels Mask, Threshold Mask - Keep.
Current behavior: Single-mask-in, single-mask-out utilities.
Recommendation: Keep. These map cleanly to the current channel stream model because
a single channel and a mask both behave as scalar fields.

Luminance Mask - Keep / Needs Fix.
Current behavior: Converts image input to a mask output by luminance.
Risk: On channel-derived streams, the image may already be a single-channel field
stored as RGB gray. This is acceptable but should be documented in UI text.
Recommendation: Keep. Add clearer labels/help later.

Solid Color Image, Color Gradient Image, Square, Circle, Text - Keep / Needs Fix.
Current behavior: Procedural image sources generated in RenderPipeline.
Risk: Reference canvas behavior for generators is less explicit than image-file
sources. Generators currently depend on the active render canvas dimensions.
Recommendation: Keep. Later, expose generator canvas/reference sizing explicitly.

Mix / Blend - Keep / Needs Fix.
Current behavior: Two image inputs plus optional factor mask. Supports blend modes,
including alpha-over in renderer types.
Risk: Mixing channel-derived image streams is possible, but semantics need clearer
documentation. Factor masks and scalar channels are compatible, but UI should explain
what is being mixed.
Recommendation: Keep. Add channel-lineage display and test multi-source resolution
behavior.

Channel Split - Keep.
Current behavior: Splits an image/full stream into R, G, B, and A outputs. If source
image has no alpha, alpha is treated as generated/full opacity in the current model.
Recommendation: Keep. This is core to the new professional channel workflow.

Channel Combine - Keep.
Current behavior: Recombines R, G, B, A scalar inputs into a full image. Missing RGB
defaults to 0.0 and missing alpha defaults to 1.0. Uses the same rules as channel-mode
Output.
Recommendation: Keep. Later add UI text for reference canvas choice.

Registered layer nodes by category

Transform / Canvas
Crop - Keep / Needs Fix.
Type ID: Crop. Class: CropLayer.
Notes: Crops by remapping/blanking within the current fixed canvas, not by changing
document dimensions. Safe enough as an effect, but should be described as crop mask
or crop-in-place until true reformat nodes exist.

Rotate - Keep / Needs Fix.
Type ID: Rotate. Class: RotateLayer.
Notes: Rotates within the fixed canvas. It does not create a larger canvas to fit
rotated bounds. Needs clear semantics in a professional node library.

Flip - Keep.
Type ID: Flip. Class: FlipLayer.
Notes: Simple transform that maps well to the current pipeline and channel streams.

Expand Canvas - Rework.
Type ID: Expander. Class: ExpanderLayer.
Notes: The shader simulates padding inside the current fixed-size render target.
It does not truly resize or reformat the raster. This should become a real Reformat
or Canvas Resize node later, or be hidden until the render graph supports dynamic
canvas changes.
Current registry metadata: Experimental plus ReworkBeforeExpose. It remains visible
for now but is labeled as experimental in the node browser.

Composite
Background Remover - Needs Fix / Advanced UI Candidate.
Type ID: BackgroundPatcher. Class: BackgroundPatcherLayer.
Notes: Useful and already has an expanded node surface plus canvas color-pick tool.
However, flood mask, brush mask, antialias, and patch controls are placeholders or
unused state. Keep the concept, but mark as incomplete until those features are
implemented or removed from the code.
Current UI metadata: Advanced editor eligibility now comes from NodeSurfaceSpec
RichExpandedSurface instead of being granted only by hardcoded type-ID checks.

Alpha Protect - Rework / Hide/Remove Candidate.
Type ID: AlphaHandling. Class: AlphaHandlingLayer.
Notes: The layer depends on ExecuteWithSource and compares processed pixels against
the original source alpha. That made sense as a website-style alpha preservation
pass, but it is awkward now that alpha can be split, edited, and recombined directly.
Recommendation: Rework into explicit alpha-channel tools or remove/hide from the
node browser after migration review.
Current registry metadata: Deprecated plus ReworkBeforeExpose. It is hidden from the
add-node browser but the descriptor remains registered for project loading.

Immediate audit conclusions
The library is powerful but uneven. The first metadata pass is now in place, so the
best next move is not mass deletion; it is compatibility review, targeted rework,
and test coverage around the newly labeled policies.
The strongest keepers are the graph-native routing/combine/scope nodes, simple scalar
adjustments, basic blur/denoise nodes, masks, and generators.
The strongest rework/remove candidates are Alpha Protect, Expand Canvas, Text Overlay,
and the unregistered aggregate layer files.
The strongest advanced UI candidates are Background Remover, 3-Way Color Grade,
Palette Rebuild, Text Overlay, Noise, Block Shift, Analog Video, and Tilt-Shift Blur.
