# Persistence and sources

Read when changing saving, loading, import, export, disk caches, discovery or deletion. Distinguish original inputs, authoritative project data and rebuildable derived data before choosing an operation or destination.

## Keep original inputs separate

Original camera RAW files remain read-only. Import may create project-owned copies and derived assets through the established storage path. A source path or provenance record does not grant permission to overwrite or remove that source. Export must not resolve to an original camera file either.

Gallery working projects live under `<photo folder>/Closet/Projects`. Their immutable managed assets share the owning Closet's content-addressed `Assets` directory; individual project folders are not independently portable. Resolve committed assets through `ProjectStore::ResolveAssetFile` or its stream interface, rather than constructing a path from `projectAssetPath`. A complete portable `.stack` collects its own dependencies. Copying a whole workspace requires its Closet as well as its originals. Browsing alone does not ingest sources, and shared assets are not automatically reclaimed.

Editor SDR PNG, HDR JPEG, HDR PNG, graph-capture PNG/BMP and Composite PNG exports use `FileSave::ExportFileTarget` captured before rendering and encoding. The resolved target and its file identity stay attached to that operation; publication rechecks them and stages in an exclusively owned sibling directory. Editor export validates the destination extension against the selected format and rejects known original image-source aliases. New destinations for these exports, including Queue outputs, are published without replacing a file that appeared later. Existing-target replacement is atomic, but the checks are not a cross-process compare-and-swap or a power-loss durability guarantee.

For destructive operations, establish what the application owns and resolve the actual target. Use the existing path and store helpers where suitable. On Windows, aliases, case differences and path normalization matter. Check affected open projects and pending users before removal; recheck at execution if a queued action can outlive the original decision. Do not infer ownership just from an extension or a folder's display name.

## Save a deliberate model

The saved representation describes enough data to reconstruct the project. It is not a dump of C++ objects, widget fields, pointers, GPU handles or worker state. Decide whether a new value is authored data, a preference, transient state or a cache before adding it to serialization.

A reserved document identity, name, destination or dirty flag does not establish saveable content. Empty tool drafts must not create placeholder projects. The editor's content check gates save commands and snapshot capture; actual bracket selections use the bracket draft writer. Preserve unfinished authored graphs and existing saved documents even without an image output. Thumbnail absence, transparency or dimensions are not evidence that a project can be discarded.

View Transform owns the saved `sdrBrightness`, `sdrHighlightDetail` and `sdrSaturation` output adjustments. New views enable the HDR-derived SDR finish. When loading an existing layer/recipe without these fields, use neutral brightness/color and zero highlight-detail mixing to preserve its authored SDR appearance. The View control's Match HDR appearance action explicitly opts an existing edit into the new finish. Preview SDR is transient and is not part of the saved recipe or processing identity.

Node notes are saved presentation metadata. Ordinary graphs serialize them beside node titles; RAW layer graphs retain owned-node notes and the projected source/output notes in their document. Commit and history restoration must not invalidate image processing or refresh Gallery image covers. Both history owners distinguish annotation edits and restore text by node identity without replacing accepted source data, pending analysis or active captures. Other non-processing metadata edits are not automatically annotation-only history. Edit buffers, wrapped-line caches, scrolling and the F-key reveal state are transient and are not saved.

Capture a consistent project revision through the established save path. Writers should consume that captured data rather than query whichever editor happens to be active later. Include the assets and metadata required by that revision. Preserve edits and renames made after capture when acknowledging completion.

Managed saves reuse the latest prepared cover; settled render adoption refreshes that rebuildable preview. Saving or closing does not synchronously read back the GPU to obtain a newer cover. A newer live bracket revision that accepts a completed save retains both its auxiliary result and master asset records. In-memory source-set edits keep their payloads in memory; do not externalize them into a transaction that will be aborted.

For Save As, inspect how current live edits, source assets, project identity and destination are captured. Verify that switching the saved baseline to the copy does not overwrite the original or discard a later edit. Do not reuse an old saved snapshot as if it necessarily contains today's graph or timeline.

Use the storage transaction and revision rules already in place. Preserve the last valid project if a write fails, and distinguish commit failure from a failed rebuildable preview or index update. Atomic replacement and power-loss durability are different guarantees; do not claim either without inspecting the relevant platform operations.

## Load and publish deliberately

Decode and validate a candidate before replacing live state. Workspace preflight reads the saved composite presentation and timeline through their production readers before resetting the current project; composite state is published only after its isolated candidate parses successfully. Keep asynchronous load completion attached to the receiving project and operation. Define what happens if another load starts, the project closes or the candidate fails after partial application. Rejection must not silently discard another operation's completion. Recovery should retain the old document's identity, dirty state and storage relationship.

Gallery-created editors use the lightweight View initialization path: reuse the shared RAW renderer and initialize Graph/node-browser workers asynchronously at their first consumer. Required GLFW context setup remains on the supported thread; worker readiness is a pending state, not a load failure. Adopt completions through the existing bounded main-thread pump, and defer optional presentation analysis during the opening flight. Presentation timing must never gate document loading or impose a minimum spinner duration.

Rebuildable MultiFrame cache readers turn malformed metadata, truncated payloads and restoration exceptions into diagnostic failures, not a permanently busy processing state. Readers validate payload lengths before allocating decoded planes, and HDR cache verification hashes the existing header/payload spans without duplicating the complete payload. A failed HDR read leaves the caller's previously accepted result intact.

Keep catalog discovery and filtering separate from authoritative document storage. Publish catalog changes after successful writes and invalidate derived listings through the established mechanism. A Gallery refresh must not mutate open project data to make its display agree. Missing or failed disposable covers must not remove a valid saved document from its Gallery family or prevent opening it. Publish saved-project browsing metadata before whole-folder source verification; path/size thumbnail hints are not verified processing inputs. Normal Gallery browsing uses saved covers or original-image thumbnails and never evaluates unopened project graphs to manufacture a cover. Refresh edited covers from the opened project's settled render; explicit comparison previews remain a separate user action.

The permanent Gallery owns the registered source folders and saved browsing scope. Each project tab retains its own source-folder provenance; navigating Gallery must not broadcast a new source root into other projects. All Folders is a derived browsing projection, not a storage root. Its root-qualified display keys must be converted back to the owning folder's native source keys before thumbnail work, and its combined catalog must never be persisted into one folder. Capture the origin when queuing an open rather than consulting the later active folder. Source-folder checks run on workers. Missing or inaccessible roots remain registered and display as offline; locally cached catalogs and thumbnails remain browsable. Reopening/rescanning reconnects them without deleting browsing history. Folder ownership/grouping preparation must not read the source drive on the Gallery input/drawing thread. Gallery catalogs are stored locally, with a read fallback for an existing managed catalog.

Only the current project format is supported. The graph reader accepts schema 22 and the RAW recipe reader accepts version 29; obsolete generations are rejected, rather than converted or silently reset to defaults. Graph loading remains transactional, preserving the live project. Do not add old-project migrations or legacy execution modes. Advance the schema when saved semantics change rather than silently reinterpreting obsolete data.

Design paths, file access and capability handling for the supported Windows audience. Use application configuration and platform helpers rather than this machine's folders, hardware or developer-installed dependencies.

Bracket working folders created by BurstEngine/ScratchDirectory carry a versioned ownership marker and an exclusive Windows file handle. The desktop worker inherits that handle; cleanup must reacquire it exclusively after all owners exit. Startup submits one background recovery pass over marked 32-hex session folders directly under Cache/BurstSessions and Cache/Bracketing. Unmarked legacy folders and reparse points are left alone. Worker-exit cleanup is off the UI thread; interrupted cleanup leaves the marker for startup recovery. Originals, project stores and managed asset directories are not cleanup candidates.

Gallery tile pixels are disposable, demand-generated PNGs owned by `GalleryTileCache` under `GalleryTiles-v1`. The default disk limit is 1 GiB (maximum 2 GiB), with a 30,000-entry ceiling and eviction before writes. Metadata-based browse keys are not authoritative source identities. Full RAW decoding and project asset materialization retain content verification. Settings > Storage changes limits and clears only this owner’s tiles; cache failure must not fail an otherwise successful image decode.

Bracket scratch writes use a cross-process admission ledger under their owned session. The default combined allowance is 16 GiB, configurable from 4 to 64 GiB, and admission checks 2 GiB of free-disk headroom. Streaming writers return unused chunk reservations at close, and consumed transport files return their bytes after successful removal. Cached intermediate reservations remain conservative until session release. Lowering the limit blocks new admissions rather than deleting active files. Temporary transfer/inspection assets retain their scratch owner through lazy consumers. Saved results, managed assets, and older unmarked directories are not included in automatic cleanup or the thumbnail limit.
