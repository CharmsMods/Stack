Glass navigation

Settings → Appearance → Glass left navigation bar (experimental) enables a presentation-only material on the main window's narrow left navigation rail. The rail attaches flush to the screen's left edge and reveals by widening rightward. Only its exposed top-right and bottom-right corners are rounded. It is off by default. The top toolbar, wider adjacent panels, detached windows, image processing and exported images keep their existing behavior.

The material is independently authored Stack code using the existing OpenGL renderer. It adds no external glass dependency. A small backdrop copy including a bounded 16 logical-pixel blur/refraction neighborhood, two half-resolution separable blur passes and one thickness-based refraction/reflection pass run before the ordinary sharp icons and controls. The existing buttons and project pills use thin translucent feedback and a slim selection marker rather than dark nested tiles. Icons keep their original vectors, with slightly larger glass-mode sizing and a subtle opposing-contrast halo. Press feedback starts immediately and eases away on release without moving the hit target or delaying the command. Existing reveal timing and panel-expansion behavior remain in use; reduced motion snaps the same presentation values.

Optical approximation

A rounded thickness profile supplies an approximate surface normal. Snell refraction with an index of 1.46 motivates backdrop displacement; Schlick reflectance and a directional light approximation supply fine exposed-edge highlights and a subdued underside. The interior preserves most background luminance and color, with a light neutral contrast veil. The left side is treated as a continuation beyond the viewport, not an exposed beveled edge. This is a screen-space UI approximation, not a physically complete three-dimensional glass simulation.

Boundaries and cost

The rail owns one reusable set of three RGBA8 textures and framebuffer objects on the main UI context. Capacity is reserved for the full surface plus its bounded sampling neighborhood and retained through reveal/hide animation. Valid-region clamping excludes unused capacity from sampling. The rail is capped at four million source pixels, or 24 MiB including its two half-resolution targets. Ordinary narrow-rail allocations use much less. No image readback, CPU effect implementation or processing-texture mutation is involved.

The framebuffer copy contains display-encoded UI pixels. Blur and material mixing deliberately operate in that display domain, not scene-linear HDR. sRGB conversion is disabled only during this material pass and restored afterward. The canvas outside the rail is not shaded. This is a UI material, not a color-grading operation.

Failure and compatibility

GPU initialization or allocation failure latches a diagnostic shown by Stack's notifications. An emergency solid navigation background keeps controls readable on the failure frame; following frames use standard navigation rather than emulating glass on the CPU. Turn the option off and on to retry. Disabling the option or shutting down releases its GPU resources on the owning context.

This first version intentionally covers only the main-window left navigation rail. It does not change detached viewport rendering or promise Apple Liquid Glass visual equivalence. Normal appearance remains available by switching the option off, including when reduced transparency is preferred.

Verification

C++17 syntax checks pass for the changed renderer, navigation, settings and shell translation units. The exact shaders compile/link on software Mesa; synthetic shader checks establish finite output, unchanged pixels outside the material rectangle and exclusion of stale allocation padding. A bounded test of the production renderer with the pinned Dear ImGui OpenGL backend passes default-off equivalence, panel isolation, transparent rounded-corner preservation, shrink/grow resize, disable/re-enable and repeated shutdown, with no OpenGL errors and restored framebuffer binding. Synthetic renders with grid and broad curved color bands were visually inspected for lensing, bounded blur and sharp foreground glyphs. Production control checks cover hover, immediate press, release-click timing, selection, interruption, disabled controls and the reduced-motion branch; native OS preference detection was not tested. These checks do not establish a full Windows application build, physical-driver performance, injected GPU-failure recovery or final visual quality across themes and displays.

Design references

Apple's Meet Liquid Glass and New look of app icons informed visual assessment: emphasize lensing, preserve transmitted color and use thin foreground control treatments rather than glass stacked on glass. Apple's published Icon Composer, clear Dock and glass-clock imagery were inspected as references. No reference image or implementation code is included in this feature.
