Glass navigation

Settings → Appearance → Glass left navigation bar (experimental) enables a presentation-only material on the main window's narrow left navigation rail. It is off by default. The top toolbar, wider adjacent panels, detached windows, image processing and exported images keep their existing behavior.

The material is independently authored Stack code using the existing OpenGL renderer. It adds no external glass dependency. A small backdrop copy including a bounded 16 logical-pixel blur/refraction neighborhood, two half-resolution separable blur passes and one analytic edge-refraction/rim pass run before the ordinary sharp icons and controls. The existing buttons and project pills gain a retargetable hover sheen and selected rim. Press feedback starts immediately and eases away on release without moving the hit target or delaying the command. Existing reveal/expand motion and reduced-motion behavior remain in use.

Boundaries and cost

The rail owns one reusable set of three RGBA8 textures and framebuffer objects on the main UI context. Capacity is reserved for the full surface plus its bounded sampling neighborhood and retained through reveal/hide animation. Valid-region clamping excludes unused capacity from sampling. The rail is capped at four million source pixels, or 24 MiB including its two half-resolution targets. Ordinary narrow-rail allocations use much less. No image readback, CPU effect implementation or processing-texture mutation is involved.

The framebuffer copy contains display-encoded UI pixels. Blur and material mixing deliberately operate in that display domain, not scene-linear HDR. sRGB conversion is disabled only during this material pass and restored afterward. The canvas outside the rail is not shaded. This is a UI material, not a color-grading operation.

Failure and compatibility

GPU initialization or allocation failure latches a diagnostic shown by Stack's notifications. An emergency solid navigation background keeps controls readable on the failure frame; following frames use standard navigation rather than emulating glass on the CPU. Turn the option off and on to retry. Disabling the option or shutting down releases its GPU resources on the owning context.

This first version intentionally covers only the main-window left navigation rail. It does not change detached viewport rendering or promise Apple Liquid Glass visual equivalence. Normal appearance remains available by switching the option off, including when reduced transparency is preferred.

Verification

C++17 syntax checks pass for the changed renderer, navigation, settings and shell translation units. The exact shaders compile/link on software Mesa; synthetic shader checks establish finite output, unchanged pixels outside the material rectangle and exclusion of stale allocation padding. A bounded test of the production renderer with the pinned Dear ImGui OpenGL backend passes default-off equivalence, panel isolation, shrink/grow resize, disable/re-enable and repeated shutdown, with no OpenGL errors and restored framebuffer binding. A synthetic panel was visually inspected for bounded blur and sharp foreground text. These checks do not establish a full Windows application build, physical-driver performance, injected GPU-failure recovery or final visual quality across themes and displays.
